# GitBook 对照剩余功能的完成标准

本文件是实施清单，不把计划、局部代码或本地测试当成正式站已完成。

## 20 外部嵌入

- 编辑器粘贴链接、预览、保存、审核、阅读和 PDF 的网址与说明一致。
- 外部内容默认不连接第三方；员工主动点击后才加载。
- 对未知网址，必须有可读的链接卡片；若要网页摘要，不能由服务器任意抓取内网或员工私有网址。只有确定了安全的数据来源和支持范围，才能标记为完整。

## 26 简体中文与英文

- 结构参考 GitBook 的不同语言空间／站点变体（https://gitbook.com/docs/guides/content-organization-and-localization/localize-your-docs-with-variants-in-gitbook），但内部资料仍沿用 JUYU 的逐篇权限与二审。
- 同一资料有独立的中英文标题和正文；英文由人工按英语习惯撰写，不能用机器直译占位。
- 英文稿按英语母语读者的阅读习惯重新组织标题、步骤、按钮文案和示例；审核时检查语气、术语、可读性及业务含义，不能只检查字句是否对应中文。
- 英文 UI 文案和英文内容分别验收。术语表固定 JUYU 产品名、角色、功能与流程名称；遇到中文专有流程时先解释其含义，不生硬逐字翻译。
- 两种语言各自保存、二审与发布。切换语言只显示已发布且当前员工有权阅读的版本。
- 目录、搜索、收藏、最近浏览、引用、PDF 和更新日志不能因语言切换重复或泄露未发布内容。
- 编辑者能明确看到缺少英文稿、待审核或已发布的状态；无英文稿时回到中文并清楚说明，不显示假译文。

## 27 历史正式版本

- 只列真正发布过的版本；草稿、退回稿与未发布审核稿不进入员工版本选择。
- 每次打开历史版本都重新核对员工身份、当前资料权限及当时附件权限；下线与权限收紧后不能靠旧网址继续读取。
- 历史版清楚标记版本与时间，不能把收藏、反馈或 PDF 错记到当前版。

## 28 AI 文档助理

- 回答只能引用员工当前有权阅读的正式资料，明确列出来源；找不到依据时直接说不知道。
- 每次检索与资料读取都按当前会话权限复核，权限收紧后失效；不把内部原文发送给未经批准的外部提供方。
- 管理员有开关、用量限制、错误回退与可审计记录。提供方和数据处理边界确定后才可上线。

## 29 外部 AI 文档访问

- Markdown、LLM 索引与 MCP 按同一授权策略生成，不能通过公开 URL、缓存或工具参数绕过权限。
- 明确机器账号、撤销、速率限制、版本与引用来源；公开发布需要另行明确哪些资料可公开。

## 30 交互式 API 文档

- 可导入并验证 OpenAPI，清晰呈现路径、参数、响应与示例；敏感头和令牌不得写进正文或日志。
- “试发请求”默认关闭；启用时只能对明确允许的目标和账号使用，防止从浏览器代发内部危险操作。

## 31 条件内容与动态变量

- 条件只依据受信任的当前身份与权限，不能由读者自行输入后解锁受限内容；不满足条件的内容不发送到浏览器。
- 变量有定义、预览、发布快照及缺值回退；正文、搜索、PDF 与历史版结果一致。

## 32 第三方集成块

- 每个集成有明确提供方、授权范围、失效状态、点击前网络边界与安全的后备链接。
- 新集成不能直接接受任意脚本或外部 HTML；编辑、二审、发布和员工阅读显示一致。

## 33 嵌入其他产品

- 嵌入只在明确允许的产品来源显示，仍要求当前用户登录与逐次阅读授权；不能把内部资料转成公开 iframe。
- 手机尺寸、主题、导航、登出和错误状态有专门验收；来源撤销后旧嵌入立即失效。

所有项完成后，还需运行整套测试、应用正式迁移、核对部署版本，并以真实 Support、OPS、Admin 账号检查正式站；这一步完成前只称“本地实现”。
