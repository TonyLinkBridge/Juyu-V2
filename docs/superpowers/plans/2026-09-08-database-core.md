# T008 · 核心数据库与事务

已确认范围：把 T005/T006 规则持久化到 PostgreSQL，为之后 Supabase 集成打基础。本轮只用临时本地 PostgreSQL，不读取真实凭据，不更改旧站。无需多人实时编辑服务。

## 设计

- 私有 juyu schema：members 成员映射；documents 状态及正式/工作版本指针；revisions 不可变快照；reviews 每次提审记录；audit_log 追加历史。
- 角色仍由服务端验证 Clerk 得到，成员表只映射身份与禁用状态。当前仓储接口接收可信 Viewer，不能直接作为公开 API。真实身份、授权和应用数据库角色见 T010–T016。
- PostgreSQL pg 驱动显式接收 Pool；同一连接 BEGIN、行锁、序号比对、复用领域状态机、保存版本/审核/状态/审计、COMMIT。失败全部 ROLLBACK。
- 读取完整聚合使用一致快照；修改先锁 documents；活动成员在事务中复核。审核记录保留具体版本和每轮结果。
- 复合外键禁止跨文章指针；不可变触发器保护版本与审计；所有表开启 RLS 且默认不向客户端授权。发布状态必须对应有效批准记录。
- SQL 迁移由显式 runner 应用，记录校验和且重复执行不重建。禁止网站启动时自动迁移。
- 正文沿用当前领域模型 string，BlockNote 结构化正文转换在 T031 处理；本次不声称已完成编辑器集成。

## 执行顺序

1. 安装 pg 与仅测试使用的 embedded-postgres，临时目录/随机端口/回环地址启动真实数据库。
2. 先写集成验收：空库和重放、完整流程、审核权限、版本不可变、并发编辑/发布单胜、故障回滚、迁移回退重建。
3. 编写版本化 SQL、迁移执行器、事务仓储；保留领域规则为唯一应用状态机。
4. 跑实际 PostgreSQL 集成测试及既有规则、lint、类型检查和构建；独立代码审查并修正问题。
5. 记录证据后完成 T008；Supabase 云端、RLS 实际身份验收和生产备份恢复保持待办。

## 验收边界

迁移回退只在本轮新建的临时测试库执行，并删除临时数据库目录；不是生产数据恢复方案（T060）。不提供公开创建成员或传入角色的接口。线上发布、认证、UI 不在本轮完成范围。
