# T015 成员与角色实施计划

按已批准的 T015 和本地优先要求在当前 Juyu V2 工作目录执行。此目录没有 Git 仓库，不创建或改动来源项目。

目标：后台成员列表、三种角色修改、资料库停用/恢复、可核对的审计，以及可信身份到受限数据库的绑定。首位管理员由 T016 实现。

设计：Clerk 是角色来源；每次业务请求重新核验公司身份并读取角色。数据库保存成员及角色观察值，观察值不代替 Clerk 验证。应用停用独立于 Clerk 全局封禁。成员必须至少成功通过一次公司验证才进入目录，既有目录可用于恢复被停用成员。只向 Clerk 合并 role 字段。

跨服务失败：用独立受限 issuer 连接串行化成员操作，先持久化 pending 记录，再写 Clerk 并回读，最后原子写审计和完成状态。pending 目标禁止业务访问；异常不自动重试写入。核对操作只读取 Clerk 并记录实际结果。核对和修改共用会话锁，不能与仍在执行的请求重叠。保留结果不确定状态，禁止静默成功。

管理员保护：禁止自己降权/停用，并在同一串行流程重新核实操作人的公司身份、角色与本地启用状态。这是较严格的最后管理员保护；两个管理员交叉降权不能同时成功。Clerk 控制台的外部更改无法由应用阻止，下一请求按新角色关闭访问。

- [x] 数据与绑定：新增 0004_members.sql、members/store.ts、authentication/member.ts；先添加数据库和角色测试，验证失败，再实现。受限 runtime 不能直接改成员或操作记录，issuer 不得为 owner/bypass 账号。
- [x] 成员操作：members/service.ts 定义 list/change/reconcile；测试自降权、禁用、冲突、权限变更、结果不确定、审计和并发。
- [x] 接入与界面：配置受限连接，authorization/application.ts 绑定当前可信身份；后台 members 页面和 API 使用相同服务；写请求检查精确 Origin、JSON 类型、输入大小和允许字段，禁止客户端指定操作者。
- [x] 验收：单元、真实临时 PostgreSQL、生产构建浏览器检查，以及 lint/typecheck/build；独立复核权限和失败路径；更新 TASKS/README 和验收记录，云端验收保留待办。

固定限制：不写真实账户或环境密钥、不部署、不自动迁移生产库、不用 service role 替代受限 SQL 连接。角色缺失或非法一律拒绝，不自动授予 Support/Admin。

实施复核补充：普通身份检查使用共享锁，成员写入用独占锁；拒绝无变化角色写入，非匹配核对保留 pending；人工恢复必须先确认原请求结束；成员历史由触发器防改写。
