# Juyu V2 · 源码来源与移植规则

日期：2026-09-08。对应第一阶段的 T003。

## 本次完成什么

建立三个本地来源的文件级基线，记录 85 个源码/参考文件的路径、SHA-256、用途和迁移限制；将员工端 21 项需求对应到 GitBook 原始文件；保存三份原样许可文本。核对 site 原有 UPSTREAM.json 的 15 个 GitBook 哈希，全部与当前提供的原始文件一致。

T003 建立时没有运行时移植。T017 已将六个 GitBook 文件的平面目录分支或样式接入 V2；T018 增加分组分支并调整树接线；`actualRuntimeMigrations` 记录来源、目标与改编摘要。其他候选文件仍未迁移，不能把来源定位当成页面完成。

## 三个来源怎么用

| 来源 | 可以拿来用 | 必须另外处理 |
| --- | --- | --- |
| gitbook-main | 阅读布局、目录、正文块、搜索展示、反馈、主题、PDF 等界面源码 | 原项目依赖 GitBook API、文档结构和内部组件包；要适配自己的数据、路径、样式和权限，不能把整套源码复制后当成可独立运行的内部资料库。 |
| site | Clerk/Supabase 的服务端组织方式、已适配的 GitBook 阅读组件、部分编辑与历史处理方式 | 旧权限、附件授权、首位管理员初始化、发布事务和内容结构按 V2 要求重做或补齐。 |
| Square UI Tasks | 看板、卡片、分组、筛选、侧栏和顶部布局 | 替换演示内容，接入真实审核命令和数据库；不继承随意改变状态的 store。 |

`site` 已改编的阅读组件是过渡参考，原始 GitBook 文件仍是来源依据。它的 README 描述哪些结构保留、哪些数据接口替换；15 个上游哈希匹配只证明原文件对应关系，不证明 site 改编后的所有行为都正确。

## 已确认不能直接照搬的地方

1. **旧角色多一个 Trainer。** `site/lib/roles.ts` 实际包含 support/ops/trainer/admin；V2 只保留 support/ops/admin，且只有 Admin 能编辑。
2. **旧首位 Admin 以 Clerk 用户总数判断。** `site/lib/clerk-server.ts` 的 `assignInitialRole` 使用 totalCount===1。V2 应在公司邮箱及 Workspace 验证通过后，用数据库一次性初始化事务分配，不能只看人数。
3. **图片 GET 缺少资料级授权。** `site/app/api/article-images/route.ts` 的带 path 请求通过登录检查后直接下载图片。V2 下载前要查文件属于哪篇资料、哪个版本，再按阅读权限判断；此项是源码检查结论，不是对旧生产站发起越权测试。
4. **旧 Supabase 客户端使用 service-role。** 见 `site/lib/supabase-server.ts`。迁移不能只把前端按钮藏起来；每个服务端入口仍须授权，并落实数据库、私有存储与缓存边界。
5. **旧分类更新不能直接当成新层级模型。** 分类重命名、嵌套分组、文章关联与可见范围需用稳定 ID 设计并验收。
6. **Tasks store 只有浏览器内存数据。** `templates/tasks/store/tasks-store.ts` 用 Zustand 和 mock-data 初始化，并允许直接更新 status，没有数据库持久化。V2 必须调用审核命令，不能把这个 store 当成业务后台。
7. **导入导出菜单不是已完成的功能。** `import-export-dropdown.tsx` 只有菜单项，没有相应处理逻辑；收入图表不属于内部资料库范围。
8. **BlockNote 不等于完整后台。** 保存、冲突处理、权限、审核和历史由自己的系统负责；第一版明确不接 Liveblocks。

## 文件记录

- `SOURCES.json`：三个来源的文件校验值（原基线 85 个，T017 补充目录依赖）、用途、21 项功能映射、许可快照和实际移植记录。
- `READER_FEATURES.md`：阅读端 21 项功能的白话对应表。
- `licenses/`：从用户提供目录原样保存的许可文本。

GitBook 与 site 中已改编的 GitBook 目录附带 GPLv3 文本；Square UI 附带 ln-dev UI License。site 根目录未发现 LICENSE 文件，不能据此把整个 site 都标为 GPL 或 MIT。这里记录收到的文件与许可，不作混合源码对外分发授权的结论，也不因此阻止当前已授权的本地来源整理。

## 后续实际移植时必须补充

每次复制或改编文件，在 `actualRuntimeMigrations` 增加：来源文件 ID、V2 实际目标路径、改编后 SHA-256、改动摘要、适用许可引用和验证记录。只在原始字节一致时标为原样复制；改过数据接口、样式或交互就标为改编。新增的 JUYU 胶水代码单独说明。

若源文件 SHA-256 变化，重新检查差异再更新基线，不默默接受。GitBook 和 Tasks 是没有可确认 commit 的下载快照，以文件哈希识别；site 记录的 HEAD 不代表其工作区没有本地改动。

不复制 `.env`、会话、密钥、node_modules、旧数据库或模拟身份配置。没有改动用户提供的三个原始目录。
