## 1. 登录与进入资料库 — 当前可验范围正常

![员工登录](../../output/verification/T057/login-light-mobile-viewport.png)

真实首页维持员工登录入口，管理员入口独立。跳到主要内容后，Tab 从正文后的可用控件继续，而不是回到顶部品牌；原生锚点不要求非交互 main 必须成为 document.activeElement。登录未配置时，按钮明确不可用，不伪造登录成功。

## 2. 员工阅读 — 当前样例正常，真实资料待验

![桌面阅读](../../output/verification/T057/reader-light-desktop-viewport.png)

![手机深色阅读](../../output/verification/T057/reader-dark-mobile.png)

保留左目录、中央正文、右侧小目录；手机收起文章目录并调整小目录位置。顶部搜索、面包屑、公告、标签、反馈、PDF 入口、回到顶部和页脚均沿用当前已实现组件。反馈模拟服务失败时有重读入口，正文继续可读。

## 3. 后台工作台 — 已修复手机入口过密

![修复前手机后台](../../output/verification/T057-before/workspace-mobile.png)

![修复后手机后台](../../output/verification/T057/workspace-light-mobile-viewport.png)

此前 17 个并列入口把筛选和待办内容挤到页面下方。现在保留“新建文章”和“员工资料库”，其余入口集中在“更多管理工具”。采用浏览器原生 details/summary，不依赖额外客户端脚本；Enter/Space 展开收起，Tab 进入链接，关闭后内部链接退出键盘序列。320 像素宽度下搜索框位于 600 像素以内，页面没有横向溢出。桌面仍可切换看板/列表，手机使用列表。

状态列数量原本在通用 span 上使用 aria-label，现移除无效标签，由该列标题和已有“本页 / 共计”文字提供数量上下文。曾尝试补充隐藏文字，整站回归发现横向溢出后移除重复说明，并以专项检查确认恢复。

## 4. 编辑与二审 — 已修复名称和深色链接

![深色二审](../../output/verification/T057/decision-dark-desktop-viewport.png)

正文输入框原本只有外框写了“文章正文”，实际 BlockNote textbox 没有可访问名称。现在通过 BlockNote 的 domAttributes 为真正的输入框命名，移除无效外框标签；键盘可聚焦、也能离开编辑框。

编辑、二审和封面原文件链接原本使用按钮背景色变量，深色模式下测得对比度约 2.62。现使用适配主题的文字颜色变量，最终自动对比度规则不再报告该问题；按钮样式沿用原配置。

## 5. 功能开关与失败状态 — 当前样例正常

![设置读取失败](../../output/verification/T057/features-error-light-mobile-viewport.png)

成功读取、保存确认、无法读取和内容空白分别处理。后台读取失败不会显示虚假的零篇文章；功能开关读取失败不填入默认设置。编辑器加载提示及失败恢复仍由 EditorLoader 提供；真实网络环境下的加载体验待连接服务后验收。

## 自动规则需要人工判断的项目

axe 的 incomplete 单独保存在原始 JSON，不算自动通过：移动菜单关闭时的 aria-controls（源码存在同 id 的 dialog，已有打开/关闭/焦点回归）、回到顶部装饰箭头的非文本对比度、移动目录中隐藏链接的重叠判断。本轮没有删除这些结果或宣称读屏软件实际通过。
