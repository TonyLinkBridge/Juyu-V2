# 首次使用引导与账号记忆验收

日期：2026-10-09。范围：在已有 Cult Onboarding 使用指南上补齐首次提醒、账号记录和失败恢复。

## 实际行为

- 登录身份确认后，没有本版记录的账号会收到非弹窗提示卡，不自动抢走编辑焦点。点击「开始引导」才打开现有分步指南；「暂时跳过」直接记录跳过。部署后，尚无记录的旧账号也会收到一次提醒。
- 员工与后台分别保存 completed/skipped、版本号 1。完成或跳过后不再自动提醒；头像菜单「使用指南」保留，可随时重看。未完成时主动关闭视为跳过；跳过后可以重看并完成，已完成记录不会因普通关闭被降级。
- 使用已安装 Clerk SDK 的 `user.updateMetadata({ unsafeMetadata: { juyu_onboarding: { [audience]: { version: 1, status } } } })` 深度合并，只写当前账号当前引导，不覆盖其他个人设置或另一端的记录。不新增 API、数据库迁移、依赖、密钥或权限。unsafeMetadata 仅为界面偏好，不用于鉴权。
- 保存中禁用重复操作；失败显示重试和「本次先关闭」。10 秒无结果也显示可恢复状态。「本次先关闭」只在当前标签页抑制提示，不声称账号已保存成功。
- Fumadocs 可能同时挂载手机和电脑账号入口：自动提示由一个入口负责，提示卡和原生指南弹窗挂在 document.body，避免侧栏收起后看不见或重复显示。
- 后台角色仍来自现有服务端接线，指南不提交、审核或发布文章；页面跳转保留未保存内容的离开检查。中文/英文、深浅主题和现有 JUYU 视觉保持。

## 来源与边界

`src/components/ui/onboarding.tsx` 未修改。首次提示卡、账号偏好与失败恢复是 JUYU 的业务接线，已明确记录在 `onboarding.source.json`，不能称为整个界面都原封不动复制官方。Clerk 的深度合并依据：已安装 SDK 的 user 类型说明及[官方 User metadata 文档](https://clerk.com/docs/guides/users/extending)。

## 验收限制

本地浏览器与自动检查使用真实产品组件，但模拟 Clerk 的外部账号存储；模拟第二设备不等于已经验证生产 Clerk。真实生产账号保存、GitHub CI、部署尚未在上述本地检查中验收；提交与推送结果以 Git 记录及对应 CI Run 为准。

10 秒超时只停止界面等待，不能取消 SDK 已发出的请求。少数请求乱序时，晚到的 skipped 可能覆盖 completed；两者只用于停止首次提醒，不影响权限或内容，也不作为阅读完成率数据。
