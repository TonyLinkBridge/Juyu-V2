# T016 首位管理员与新成员开通：本地验收

日期：2026-09-08

## 已实现的行为

- 全新且尚未初始化的系统中，首位通过当前 Clerk 身份、已验证公司邮箱及 Slack Workspace 校验的无角色账号，可自动成为 Admin；后续无角色新成员默认 Support。
- 并发首次开通只保留一位首位管理员。已有成员系统以及 Clerk 已有的合法手工角色保持原安排，不重新自动授予 Admin。
- 初始化记录永久保留。首位管理员之后被降级、取消角色或停用，不会触发再次自动提权。
- 先保存唯一开通意图再申请角色写回；请求结果不明确时保留待核对状态，不重复写入角色，也不把首位名额转给其他账号。
- 只有重新读取当前可信身份并确认角色一致，才完成开通。GET 只检查；POST 不接受客户端选择用户或角色。
- 员工入口、后台登录页以及 Clerk 登录后的实际 /admin 入口共用开通检查。开通后继续接受原有权限检查。
- 后台成员列表明确标记等待开通核对的账号，并禁用其普通角色修改操作。
- 界面说明首位管理员不能审核自己的提交，需要另一位管理员负责二审。

## 尚未验收的部分

Clerk、Supabase 测试项目及公司邮箱域名、Slack Workspace 允许列表尚未配置。本次没有写入真实账号、修改真实 Clerk metadata、执行云端迁移或部署。

仍需在真实测试环境验收首次登录、Slack/邮箱准入、角色写回、前后台分流及退出。当前结果仅为本地实现与本地验收通过。

如果远端请求是否结束无法确认，账号会保持待核对状态。人工修复前需要确认原请求已经结束；等待超时或手工设置一个匹配角色本身不能证明原请求已经结束。不能通过清除初始化记录或重复授权处理。
