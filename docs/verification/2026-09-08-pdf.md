# T026 PDF 阅读与导出 · 本地验收

2026-09-08。单篇正式文章PDF页面、服务器PDF下载、权限复核打印和关联PDF附件阅读已完成本地实现；完整富内容、草稿编辑预览和真实服务验收尚未完成。

## 本次行为

阅读页新增绑定文章ID及正式版本的“PDF 阅读／导出”链接，打开独立白底阅读页；返回文章、下载PDF和打印控件放在纸张外。沿用GitBook PDFPage、PrintButton、PDFPrintControls、ImagesLoadingStatus及pdf.css结构方向，具体差异与SHA256见 `docs/sources/T026-pdf.json`。正文解析及服务器授权、生成流程为JUYU实现，不调用GitBook后端。

服务器导出单篇已发布文章，含当前标题、版本、标签、封面、基础标题/段落/列表/表格。基础管道表格已接入普通阅读和PDF的同一解析器：表头分隔行至少三个短横线，数据行需同列数，两侧竖线必填；不支持合并单元格、嵌套块或转义竖线。非表格或未支持的Markdown继续按原文显示，不静默解释外部图片。PDF重复表头，标题避免落在页尾。

附件PDF来自当前授权正式版本的文件关系，按私有 `/api/assets/:id` 内嵌预览，并保留“打开文件”链接供手机/不支持内嵌的浏览器使用。附件不会自动拼接进文章导出。安全头 `CSP: sandbox` 在独立审查的本地Chrome合成PDF iframe验收中正常显示，未删除安全限制。

## 权限与错误

`AuthorizationService.pdf` 在同一只读事务内读取正式文章、元数据及可读PDF附件，不发送存储地址或对象键。Support仍不能读取OPS/受限分类。Admin使用员工阅读端导出也只读正式版，没有借查询参数读取草稿的入口。新增稿件不影响旧正式版；版本已经替换时拒绝旧版本导出。

`exportPDF` 在生成前检查正文权限，以私有存储读取封面并校验归属、类型、声明长度及实际长度；渲染后重新读取当前身份、正式版本及附件权限，变化则丢弃生成结果。没有公开PDF缓存、供应商浏览器服务或云存储写入。Chromium使用独立无脚本、无外网的上下文，页面不导航到用户输入URL；所有正文文字转义，封面仅用服务端校验后的数据内嵌。

“打印此页”最初直接调用window.print；独立审查指出旧页面撤权后仍能点应用打印，已修复为先请求服务端 `check=1`，核对当前正式版本和封面身份，失败不调用打印。此检查无法追回员工已经读到、截图或下载的内容，也无法禁止浏览器自身的离线打印。这是读取后的正常边界，不宣称实现DRM。

客户端下载收到PDF响应后才交给浏览器，不把请求开始当成功；下线、换版、超限、忙碌和一般失败有恢复提示。打印等封面加载成功才开放，封面失败不静默打印缺图文件。所有API结果private/no-store，伪造身份和未配置服务保持关闭。

## 运行限制

新增生产依赖playwright-core 1.62.1，使用本机兼容Chromium；可用 `PDF_CHROMIUM_EXECUTABLE` 指定路径。正式部署需另准备Chromium及中文字体并再次验收，本地浏览器安装不等于部署环境可用。没有自动下载浏览器或连接远程浏览器。

当前每进程最多一个Chromium排版任务；授权及封面读取仍可并发，不是全流程全局队列。正文25万字符、封面5MiB、输出20MiB上限；图片读取15秒、启动10秒、渲染阶段25秒关闭浏览器保护。多副本全局排队、更多复杂内容/大文件和负载验收属于后续性能工作。`page.pdf`不支持timeout参数，构建检查发现后已移除，由关闭浏览器的期限控制。
