# T049 · 分类设置本地验收

2026-09-09；工程 `/Users/tony/Documents/ChatGPT/Juyu V2`。

## 功能与范围

管理员后台新增“分类设置”入口 `/admin/settings/categories`。支持创建、改名、选择上级、调整排序、设置 staff / ops / admin 范围，以及停用、重新启用。分类使用固定 UUID，改名不改变文章归属。最多100项（含停用）、10层、每篇20个分类；没有硬删除入口。同级按排序数字再按固定编号排列，与员工目录一致。使用不同数字可指定明确顺序。

分类设置是当前访问策略。移动分类、修改范围、停用会立即影响已发布内容及下级分类，保存前会再次提示确认；父级所有限制共同继承，任一父级停用就停止对员工开放。文章本身的范围仍生效，多个分类同时满足全部限制。

文章编辑器提供受控分类选择，归属随新草稿及正文一起保存和提交二审。修改草稿不会改写旧正式版分类，只有新版本发布才替换正式归属。二审、发布核对及冻结编辑器显示已保存的分类和当前范围，历史恢复保留原分类 UUID；名称和分类策略使用当前设置，不是历史权限快照。停用的已有归属可保留或移除，不能给新草稿新增已停用分类。Q&A 原有文字分组仍仅用于查找，与目录权限分类分别显示。

分类配置生成不可变版本记录（操作人、时间、配置），历史不覆盖。统一设置历史查看/恢复界面仍在 T053 范围，本阶段没有把它冒充完成。自定义表单仍为 T050。

## 数据与权限边界

GET `/api/admin/categories`、PUT `/api/admin/categories/[id]` 仅限当前公司验证合格 Admin。PUT 使用服务端身份、同源检查、JSON类型、16KB流式上限和超时；所有响应 private/no-store，不返回内部数据库错误。数据库再次检查成员停用、待同步角色、开通状态，写入等待后复核身份。

整个分类树使用同一数据库事务锁，串行化循环、深度和数量检查。版本冲突不覆盖他人修改；相同操作人、编号、完整配置和原版本的重试只能确认对应写入。保存结果不明时锁定原提交，遇到后续冲突仍不假称原提交失败；可精确重试，或明确载入服务器当前设置。未保存输入切换或离开前提示。

文章修订保存类别 UUID，数据库触发器绑定 revision_categories，运行账号不能直接改正式关联。新增修订检查ID、数量、可用分类、当前Admin及草稿/审计绑定。恢复函数仅在实际表所有者上下文保留历史关联；延迟检查标记由 BEFORE INSERT 强制赋值，运行账号不能伪造 false。旧数据升级回填现有 UUID，并保留既有资料。

员工目录、文章、搜索计数/摘要、收藏、最近浏览、图片文件和 PDF 均沿用当前 `can_read_document` / `can_read_revision` / `category_allowed`。分类改为受限后，新的请求必须重新通过这些检查；已经下载到员工设备的文件无法追回，本阶段未作此保证。
