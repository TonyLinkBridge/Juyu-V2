# T040 OPS Internal（本地验收）

## 完成范围

新增 `/help-centre/ops` 运营内部资料集合，当前有权的Ops/Admin可查看正式资料，按标题/ID稳定排序，每页30篇，有真实数量、分页、正式版本及标签。点击后进入现有GitBook派生文章阅读器；编辑、二审、发布、归档和文件保护沿用同一套规则。没有填入未经用户提供的业务流程内容。

员工阅读页和标题搜索页按当前数据库权限显示OPS Internal入口。Support不显示入口，直接访问集合页也不能读取标题、标签或数量。账号停用、角色降级、待处理角色/开通状态等重新校验。失败、无权限和有权限但尚无正式资料分别呈现，不用空列表冒充加载成功。

管理员编辑器原已支持OPS类型自动选Ops/Admin并排除普通员工选项，本轮只增加此行为的浏览器回归，不改已完成逻辑。Ops仍为只读，不能编辑、二审、发布或访问管理历史。

## 数据与权限

新增0013迁移的窄读取函数，只投影当前有权正式OPS文章的id、标题、版本与标签；撤销PUBLIC执行权，不扩大原始资料表读取策略。现有can_read_document继续限制资料类型、已发布指针、生命周期、正文阅读范围及分类祖先限制。Admin进入员工集合时仍只看可读正式版，Ops不能看仅Admin的OPS资料。

重新编辑时继续提供旧正式标题/标签/正文；下线、归档及删除后关闭后续集合、正文和文件请求。刻意构造的旧OPS类型加staff范围数据也不能绕过Support限制。私有API返回no-store；文件和PDF沿用已有发送前复核。已传送到设备的内容不能远程收回。
