# T025 文章反馈本地验收 · 2026-09-08

员工可以在已发布文章底部选择“有帮助 / 没有帮助”，填写可选说明并提交；刷新后恢复自己的反馈，也可以修改。后台新增“文章反馈”入口、按版本的汇总和逐条明细，只有管理员可访问。反馈是具名的，员工表单明确告知管理员可以查看其选择和说明。

## 实现与权限

沿用 GitBook PageFeedbackForm 的评价、说明、聚焦及成功状态结构，移除供应商追踪接口，改接 JUYU 持久化接口。与上游三档即时评价不同，当前为两档、显式提交及可修改的反馈；只有服务器确认后才显示成功。来源及目标校验见 `docs/sources/T025-feedback.json`。

沿用 `(member_id, document_id, revision_id)` 唯一键。同一员工对同一正式版本仅计一份；完全相同的重试不增加版本或数量。修改带 expectedVersion，不同的过期内容返回409，防止多页面覆盖。新正式版从独立反馈开始，管理员仍可查看旧版，且标识历史/下线，不混入当前版本。

新增 `0007_feedback` 迁移及受限 `save_feedback` 函数；员工身份取服务端当前认证，函数核对成员状态、角色、分类和正式版本。写入锁定文章行，再检查权限与版本，和发布/下线协调。运行账号没有直接反馈表写权限。GET只读本人当前有权版本；后台列表及明细单独要求Admin。评论以React文字显示，不执行HTML。

PUT要求同源Origin、JSON与最多8KB请求体，说明最多1000字符，拒绝额外身份字段；响应private/no-store。不可读文章返回404，正式版本变化与修改冲突返回409，服务错误不回传内部详情。读取反馈失败不影响文章正文；保存失败保留当前输入，冲突须重新读取，页面明确提醒重新读取会替换输入。没有在浏览器localStorage存储反馈。

后台汇总每页20个文章版本，明细每页25份，页码超范围回到最后一页；时间标示马来西亚时间。后台真实查询失败显示读取错误，实际空表才显示没有反馈。
