# Admin 本人送审撤回快捷入口验收

## 已确认范围
- Super Admin 才有批量撤回选择、按钮、服务/API/SQL 权限，成员降级后旧请求也被拒绝。
- 普通 Admin 在内容列表对本人提交、仍等待审核的资料看到「撤回送审」。四种类型一致；他人、草稿、已批准/发布资料不新增该快捷入口。
- 这是入口优化：保留原有深层单份审核管理权限，没有将已有单份 API 改为仅本人。

## 实现与安全检查
- 归属由数据库使用可信 actor ID 比较 submitted_by，不能用显示名称或邮箱代替。
- 链接到原审核管理页并携带 intent=withdraw。服务器只有确认当前人为提交者、资料活动且仍在审核并有原管理资格时才自动展开；重复或无效 intent 不展开。
- 打开、预取、刷新和取消不执行撤回；确认使用原带版本校验的撤回操作及幂等回执，不另造状态更新路径。
- 原文、版本、历史、已有正式内容和阅读链接不变；每次成功仅追加原来的 withdraw 事件。
- 管理读取附带兼容的 kind 字段，返回知识文章/OPS/Reference/Q&A 对应管理页。旧无 kind 的响应仍兼容默认入口。

## 验证
- RED：本人标记与快捷链接不存在；intent 没有展开确认，分别由单元、数据库和浏览器测试复现后实现。
- 最终 624 项单元、500 项完整数据库检查通过，类型/规范、正式构建及构建后的资源检查通过。
- 68 项桌面/手机专项通过：涵盖批量超级管理员限制、原有单份流程、四种本人快捷撤回、打开/取消不写入、一次确认、已有正式版及历史保留、对应返回链接。
- 独立只读代码复核检查批量多层权限及锁后资格、本人标记、intent 限制和导航，没有已确认待修复问题。复核未操作生产或声称独立运行测试。
- 内置浏览器连接真实临时 PostgreSQL：普通 Admin 能看到 8 份自己的快捷入口，他人对照资料无入口，批量按钮为 0。分别确认撤回四种已有正式版的本人资料；每份保留原正式版和全部修订，只追加一个当前 Admin 撤回事件。
- 9 份测试资料全部保持原正文、正式版指针与已有历史；未选中的 5 份（包含他人对照资料）仍审核中且序列不变。证据 `/tmp/juyu-own-browser-evidence-2026-11-17.json`，确认/结果图片 `/tmp/juyu-own-withdraw-confirm-2026-11-17.jpg`、`/tmp/juyu-own-withdraw-success-2026-11-17.jpg`。临时证据不提交。
