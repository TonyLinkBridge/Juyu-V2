# T030 · 管理员内容看板与列表

2026-09-09。本地实现与验收；未连接真实 Clerk、Slack、Supabase，也未上线。

## 实现与使用

`/admin` 在既有账号开通、Admin 检查后读取工作台。同一页面提供看板/列表切换，手机固定为列表。点击文章标题进入已有媒体/内容块编辑入口；新建和完整编辑由 T031 接入，指定二审/审核/发布控件由 T034–T037 接入，本轮没有拖动更改状态的功能。

看板使用六个当前流程状态：草稿、等待审核、需要修改、已经批准、等待发布、已经发布。每张卡片显示类型、工作版本、编辑人、提交人、二审人、更新时间及正式版本状态；时间为马来西亚时间。已发布文章修改后归入新草稿，同时注明“旧正式版仍可阅读”。

筛选支持标题、资料类型、当前状态和个人范围：

- 我提交的：当前流程的 submitted_by 为本人；重新编辑为草稿时原提交关系清除，不混入历史提交。
- 等我审核：当前为等待审核且本人为指定二审。
- 退回给我的：当前为需要修改且本人为提交人。

状态总数按关键词、资料类型和个人范围计算，不随当前状态选择或页码改变；列表总数则包含所选状态过滤。每页30篇，按更新时间倒序、文章稳定ID排序。看板列明确标注本页数量与实际总数，某列本页为空但实际有资料时提示筛选或翻页；越界页码收敛到最后一页。列表与看板使用同一服务器快照。

原生 GET 表单及链接保留筛选 URL，刷新后可恢复；重新筛选回到第一页。尚无文章/无匹配结果与服务不可用分别展示；读取错误不展示虚假的0条或旧数据。加载状态由 Next.js 页面加载入口提供。

## 授权和数据

- `AuthorizationService.workspace` 先验证服务器当前身份及 Admin，再通过受限数据库只读重复读事务读取。SQL 再检查 `juyu.is_admin()`，数据库角色被降级后不能凭旧 Viewer 取得内容。
- 只读取 active 资料与当前工作版本；不返回正文、历史版本、用户邮箱、文件地址或数据库错误。人物使用数据库显示名。
- 标题为参数化字面子串匹配，`%`/`_` 不作为通配符。标题最长120字符；拒绝重复参数、未知状态/类型/个人范围以及非法页码。
- `/api/admin/workspace` 仅 GET，响应 `private, no-store` 并 Vary Cookie/Authorization；POST 返回405。不会接受浏览器传入的role或actorId作为身份。
- 无新数据库迁移、无供应商连接、无真实账号写入。当前权限、版本和附件规则继续由原服务维护。
