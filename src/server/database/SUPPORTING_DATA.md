# 辅助数据结构 · T009

本次追加 0002_supporting_data.sql，不修改 0001_core.sql。当前没有新页面或公开 API 读写这些表；数据库集成测试使用临时数据库所有者。真实登录、读写授权、私有存储仍在 T010–T016。

## 公司范围

一家公司一套应用部署及数据库数据集，所有核心表和辅助表同属 juyu schema；不是多个公司共用业务库。member_id 对应 members.clerk_user_id，但存在这一行不等于公司已验证。T013 必须核实允许的公司和 Slack Workspace。未来如果支持多公司共用数据集，必须同时改造核心表、辅助表、唯一键与权限策略后做跨租户测试，不能只在部分表追加 tenant_id。

## 表与关系

| 表 | 保存什么 | 关键关联/约束 |
| --- | --- | --- |
| categories | 分组和子目录名称、顺序、范围、启停 | UUID 稳定 ID，父分类外键，不能自己作为父级 |
| revision_categories | 某版文章属于哪些分类 | 文章+版本复合外键，分类外键 |
| assets | 文件名、类型、大小、上传者、对象标识、状态 | 固定文章归属；bucket=juyu-private，对象键仅 UUID；不存公开 URL |
| revision_assets | 某版文章用到的附件、内嵌媒体、封面 | 文件与版本必须属于同篇文章；每版最多一张封面 |
| favorites | 员工收藏 | 每员工每篇文章一条，不复制标题和正文 |
| recent_views | 最后浏览的版本与时间 | 每员工每篇文章一条，版本必须真实存在 |
| feedback | 帮助与否、意见、修改时间 | 每员工每篇文章的每个版本一条；新版本单独统计 |
| search_queries | 搜索词、员工、结果总数、时间 | 稳定事件 UUID，可作为去重键；无正文或摘要副本 |
| search_results | 实际返回结果的名次、文章及版本 | 属于具体查询，记录真实版本 |
| analytics_events | 浏览、搜索点击、反馈事件 | UUID 去重键；点击必须匹配本人的查询及实际结果 |
| settings | 设置编号、键、种类和当前版本 | 仅 field/form/navigation/feature_flag/general；当前指针不能指向其他设置的版本 |
| setting_versions | 配置 JSON 对象、版本、修改者、时间 | 不可修改/删除的配置快照，修改者必须是已有成员 |
| notifications | 公告文字、可见范围、有效期、入口关联 | 目标文章或设置必须存在；目标至多一个，无任意外部 URL 字段 |
| notification_receipts | 已读或关闭状态 | 每位员工独立记录；不允许空记录或倒置时间 |

引用默认不级联删除，避免清理一条记录时误删其他历史。资料下线/回收站后，这些关联可能仍保留；读取时必须重新检查当前权限，不得因此返回旧标题或附件链接。永久删除与分析保留期须由后续受控清理任务按依赖顺序处理。

## 后续接入必须落实

- 分类树完整循环检查、移动时的并发控制、限制范围和配置审计为 T049。本次只保证存在的父级和禁止直接自指，不声称已实现完整目录编辑。
- 分类关联与附件关联是版本的元数据。T031/T034 的受控保存必须在创建新快照的事务内写入，提审后不允许直接增删关联；本轮外键不等于所有快照元数据已被冻结。当前没有相关写入口。
- 文件表不是 Storage 对象本身。T011 必须实际建私有桶、核验上传内容和大小，并验证登录、资料及版本权限；对象键猜不到不能作为授权依据。文件状态转换也由 T011 的服务端入口检查。
- 个人功能 API 必须从当前已认证会话取得 member_id，不能使用客户端自报身份。最近浏览上限、反馈更新时刻、时间采集和重试去重处理在 T044–T046。
- 搜索总数由已过滤权限的搜索返回值产生；记录到 search_results 的名次是原查询的实际名次，分页不会另从 1 开始。表关联防止点击串到别人的查询，但不会自行判断哪些结果可读、名次是否在总数内。这由 T041/T046 服务端查询与采集事务执行。
- 搜索词本身可能包含员工输入的敏感文字。T046 需明确保留期、限制可查看分析的管理员、控制采集字段；事件表不提供任意附加 JSON 以免带入正文/凭据。
- settings 的 JSON 对象只是配置存储格式。本轮没有实现字段类型、表单字段引用、导航白名单、功能开关执行或自动生成代码。T048–T053 须按 kind 严格校验结构，保护历史与写入序号；设置改名、启停、恢复等也要一起形成记录。
- 公告目标的进一步语义（例如目标设置必须是启用的功能开关）、阅读权限与公告 audience 的交集在 T054 实现。关联目标存在并不等于员工可以打开目标。
- 全部新表开启 RLS 且没有客户端策略，撤销 PUBLIC 权限；本轮另用有表权限但无 RLS 策略的测试角色验证拒绝。数据库所有者仍可管理数据，不将此测试视为生产最小权限验收。

## 验证方式

`npm run test:db` 使用本项目已有临时 PostgreSQL 夹具。supporting.test.ts 含新增结构及关联测试；core.test.ts 继续验证审核原子性及并发单胜。

升级测试先在全新临时集群建立原始 0001 及其校验和，创建已有文章，再执行正式 migrate()：只返回 0002，读回旧文章不变。重复 migrate() 返回空数组并保留辅助表行数。原始迁移版本的内容不因追加新表而改写。
