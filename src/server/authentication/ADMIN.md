# T014 · 管理员入口与访问检查

管理员使用 `/admin/sign-in`，员工使用 `/sign-in`；共用同一套 Clerk 账号与会话。后台退出终止当前 Clerk 会话并回到后台登录页，因此同一会话的员工入口也会退出。没有独立密码库。

## 信任与权限

`currentAdminAccess` 先完成当前请求的公司邮箱和 Slack Workspace 校验，再通过 Clerk Backend API 重新读取用户。只有精确的 `publicMetadata.role = admin`、未禁用/锁定、用户 ID 一致且主邮箱仍已验证并匹配公司校验结果才放行。浏览器传入角色、unsafeMetadata 和旧会话角色声明不能授予权限；没有应用角色缓存。

`/admin` 页面自己检查权限；`/api/admin/access` 和现有管理员文章接口使用 `adminOnly`。未登录返回 401，身份不符合返回 403，未配置或供应商不可用返回 503。敏感结果 private, no-store。员工页面只有通过上述检查的管理员看得到后台入口，隐藏链接不代替服务端检查。

后续所有后台页面和接口都必须使用当前请求的身份检查；不能仅靠布局或导航限制。业务操作仍须经过统一授权服务和受限事务仓储。每次读取当前角色会产生供应商请求，后续容量优化不能引入未经验证的长期角色缓存。

## 登录跳转

员工固定回到 `/help-centre`，管理员固定回到 `/admin`；失败、重试和退出分别保留各自入口。登录与回调地址先清除 Clerk 的五个重定向覆盖参数，再进入 Clerk middleware，保留 OAuth state、code、ticket 等其余参数。Clerk Provider 的允许跳转来源限制为配置的 APP_ORIGIN。

实际安装 SDK 的 RedirectUrls 回归证明，同源查询参数原本可以覆盖组件的强制目标；清理后恢复固定目标。该证据不等于已证明任意外站重定向，也不等于真实 OAuth 回调验收。

## 当前边界

已通过管理员检查时显示工作台准备页，尚不能编辑或发布。业务授权工厂仍默认返回 AUTH_NOT_CONFIGURED；状态接口只报告入口授权，不返回业务资料或用户详情。

Clerk 测试项目、公司域名和 Workspace ID 尚未配置，真实登录、退出、回调及角色变化验收待办。T015 继续角色与成员管理、受限数据库身份绑定、审计和最后管理员保护；T016 实现首个合格账号自动成为管理员。本任务没有修改真实账号、角色或数据库。
