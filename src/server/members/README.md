# T015 · 成员与角色管理

> 2026-09-10 当前接入说明：[T059 测试环境配置](../../../docs/setup/T059-test-environment.md)。下文保留各阶段历史记录；公司准入、业务授权与阅读端均已完成本地实现，当前迁移为 0001–0026，真实项目验收仍待完成。

入口 `/admin/members`。管理员可查看曾通过公司验证且角色合法的成员，修改三种角色，停用/恢复资料库访问，查看最近 50 项操作和核对未完成结果。列表每页 25 人，可刷新和翻页。无配置或供应商失败时明确显示不可用，不生成假成员。

## 当前身份与数据库

Clerk Backend API 的 `publicMetadata.role` 是角色来源，只接受 support、ops、admin。新请求重新验证当前会话、公司邮箱和 Slack Workspace，再读取当前角色。缺角色不默认授予权限；T016 已实现首位管理员与新用户默认角色的独立开通流程，见 `src/server/enrollment/README.md`。

员工正常进入 `/help-centre` 时，`bindCurrentMember` 将合格身份登记到成员目录；资料文章和文件授权由 `applicationAuthorization` 使用同样的可信身份绑定。成员表的 observed_role 是同步观察值，不能单独构造用户权限。请求上下文角色必须与该值匹配；停用成员及 pending 修改目标均不能使用数据库上下文。

普通身份验证/绑定使用同一数据库共享会话锁，可并行读取；成员变更使用独占会话锁。锁冲突返回暂时不可用。运行中的重复读事务仍受原快照约束；这不是中断已返回数据或保证在途请求立即撤销。每个新请求重新验证，未来阅读、搜索、附件和导出接口必须持续使用统一授权层。

## 应用内操作

角色修改只通过 Clerk `updateUserMetadata(id, {publicMetadata: {role}})` 合并 role，不覆盖 Slack 或其他元数据。当前锁定 SDK 的该方法只发一次请求，没有自动重试写入。直接在 Clerk 控制台改角色会在新请求被读取；应用内历史不能冒充 Clerk 控制台完整审计。

停用设置本地 `disabled_at`，仅限制此资料库，不调用 Clerk 全局 ban。Clerk 禁用或锁定账号另外由身份校验拒绝。恢复资料库访问要求目标重新通过公司验证，不会解除 Clerk 自身封禁。

禁止修改自己的角色或停用自己，即使还有其他管理员；由另一位管理员执行。所有应用内成员修改串行化，并在锁内重新核验操作者的当前 Admin 身份和启用状态。因此交叉降权不能同时成功，最后一位管理员不能从应用里取消自己的权限。无法阻止有控制台权限的人直接删除/降权 Clerk 最后管理员，应用不自动恢复其角色。

## 跨服务失败与审计

先提交 pending 操作记录，再写 Clerk；回读后将成员观察值和完成记录在同一事务提交。记录包含操作者、目标、原角色/停用值、请求目标、实际观察角色、时间及核对人。原始操作意图和完成历史受数据库触发器保护，不能改写或删除。

远端写入错误不等于未执行。结果不明时保留 pending，阻断目标业务访问和其他成员修改；不会自动重试写入。核对与修改共用独占锁。只有读到已请求的目标角色才能解除不确定状态；无变化角色请求在写入之前拒绝，不能用旧值匹配冒充完成证据。

若长时间无法核对，联系身份服务管理员确认原请求确实已经结束，必要时联系 Clerk 支持，然后才按已批准记录人工处理目标角色并再次核对。手工改成目标值本身不证明原请求结束，等待固定时长也不证明远端请求已取消。未确认前保持阻断，不能直接删 pending 记录恢复操作。

## 配置与上线验收

先由运维在目标测试库显式执行迁移 0001–0004；应用启动和页面渲染不会自动迁移。再配置 `.env.local` 或部署密钥管理中的：

- JUYU_DATABASE_RUNTIME_URL：独立受限登录，仅属于 juyu_runtime。
- JUYU_DATABASE_ISSUER_URL：另一受限登录，仅属于 juyu_context_issuer。

两者必须指向同一数据库、不同用户名，使用直连或 session pooling，禁止 transaction pooling；远程连接要求 `sslmode=verify-full`。运行时拒绝 owner、superuser、bypass RLS 或混合两种能力的账号。issuer 是可信服务端身份能力，不能暴露给浏览器。服务端 Supabase service role 不能替代这两条 SQL 连接。配置更改后重启服务。

真实验收仍需 Clerk 项目、公司域名、Workspace ID、迁移后的 Supabase/PostgreSQL 测试库及受限登录。验证三角色、外部角色变化、公司撤销、停用/恢复、两个管理员并发、远端失败核对、文章和私有附件。当前没有连接真实账户、没有修改真实元数据、没有部署。
